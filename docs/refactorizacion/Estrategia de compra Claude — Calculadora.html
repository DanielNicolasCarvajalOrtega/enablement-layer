Conceptos clave y recomendaciones

Team 2–150 usuarios

Plan self-serve. El costo de uso va empaquetado en el precio del asiento (Standard vs Premium = multiplicador de uso). Buena opción si no manejan datos sensibles o mientras hacen un piloto corto.

Enterprise datos sensibles

Mismo precio de asiento base ($20/mes), pero el consumo real se cobra a tarifa API en vez de venir empaquetado. A cambio obtienes RBAC, SCIM, audit logs, Compliance API y retención de datos personalizada: lo que pediste para pacientes.

BAA / DPA contractual

El DPA (Data Processing Agreement) es el acuerdo estándar de tratamiento de datos. El BAA (Business Associate Agreement) es específico de la ley HIPAA de EE.UU. para información de salud (PHI).

  • Para Chile aplica la Ley 19.628/21.719, no HIPAA, pero el mecanismo técnico (BAA/DPA) es el mismo que usarían para amarrar el resguardo.
  • No se activa solo: se firma contactando al equipo comercial de Anthropic.

ZDR — Zero Data Retention se solicita

Con ZDR, Anthropic no guarda tus prompts/respuestas después de responder, salvo lo mínimo exigido por ley o para prevenir abuso.

  • Requiere aprobación de Anthropic (cuenta calificada), no es un switch self-serve.
  • Aplica a la API/Enterprise; en Enterprise también puedes fijar una ventana de retención personalizada en vez de cero total.

Costo API / Claude Platform

Separado de los asientos: se paga por token, para el trabajo de agentes, MCP y RAG (DREAMS, vault, reportería).

  • Sonnet 5: $2 / $10 por millón de tokens (entrada/salida)
  • Haiku 4.5: $1 / $5 — bueno para indexado masivo y clasificación barata
  • Opus 5.5: $4 / $20 — razonamiento pesado

Tip: piloto con datos sintéticos

Antes de tener el DPA/ZDR firmado, prueben los flujos MCP con datos anonimizados o sintéticos. Actíven el flujo real recién cuando el acuerdo esté cerrado.

Tip: reutiliza el pipeline n8n

El reporte diario que ya corre por n8n + Python puede extenderse para leer la Compliance API de Anthropic y armar el dashboard de consumo/inactividad por usuario que pediste, en vez de construir algo desde cero.

Tip: mezcla de asientos

No todos necesitan Premium. Resérvalo para quienes viven en Claude Code (el equipo TI del refactor); gerencias y usuarios generales normalmente rinden bien en Standard.

Entendimiento

Esta sección explica cada concepto de la página para que cualquiera pueda leerla y tomar decisiones informadas: qué significa cada fila de la comparación Team vs Enterprise y qué hay detrás del resto de los controles de la calculadora.

PuntoQué significaPor qué importa al decidir
Rango de usuarios Team admite de 2 a 150 asientos y se compra en autoservicio. Enterprise no tiene tope y se contrata con un acuerdo dedicado (vía ventas). Para equipos de tamaño medio, Team alcanza. A partir de ~150 usuarios, o cuando se quieran negociar condiciones, se salta a Enterprise.
Precio asiento Standard (anual) El asiento base cuesta lo mismo en ambos planes: $20/mes facturando anual (en Team, $25/mes si es mensual). La diferencia no está en el precio del asiento base, sino en cómo se cobra el consumo (punto siguiente) y en la gobernanza que entrega cada plan.
Precio asiento Premium (anual) En Team, el Premium es un asiento que se paga por adelantado: $100/mes anual (o $125/mes mensual). En Enterprise no existe como asiento: el uso por encima del plan se consume vía API y se factura aparte. Team = costo fijo y predecible. Enterprise = costo variable, según el consumo real de tokens.
Consumo de uso En Team el uso viene incluido y acotado por el tipo de asiento (Standard = uso estándar de la suite; Premium = más uso y prioridad). En Enterprise el uso del contrato está incluido y el excedente se factura a tarifas de API. Si el uso es parejo conviene el paquete de Team; si fluctúa (batchs, automatización, RAG), Enterprise paga solo lo que se usa.
SSO Ambos planes permiten iniciar sesión con el proveedor de identidad corporativo (Okta, Entra/Azure AD, Google). Es el requisito mínimo de TI para adoptar la herramienta; no diferencia entre planes.
RBAC (accesos por rol) Solo Enterprise: roles y permisos finos (quién puede hacer qué, delegación de tareas administrativas). En Team todos los asientos se tratan igual. Necesario para separar poderes (TI, finanzas, usuarios) y delegar administración de forma controlada.
SCIM (aprovisionamiento) Solo Enterprise: sincroniza usuarios automáticamente con el directorio (alta y baja automática cuando entra o sale gente). En Team el alta/baja es manual. Menos carga administrativa y mejor control de accesos cuando hay rotación de personal.
Audit logs Solo Enterprise: queda registro de quién usó qué, cuándo y cómo. Trazabilidad para cumplimiento y para investigar incidentes. En Team no está disponible.
Compliance API Solo Enterprise: permite exportar logs y reportes de cumplimiento de forma programática. Alimenta el SIEM/auditoría y puede integrarse al pipeline n8n que ya existe para armar el dashboard de consumo e inactividad por usuario.
Retención de datos personalizada Solo Enterprise: permite configurar cuánto tiempo se retienen los datos y registros de la cuenta. Permite balancear resguardo y cumplimiento; es la base sobre la que se puede fijar ZDR u otra ventana de retención.
HIPAA-ready / BAA Solo Enterprise: oferta el mecanismo contractual para datos de salud (BAA, específico de HIPAA, y además el DPA estándar). No se activa solo: se firma con el equipo comercial de Anthropic. En Chile aplica la Ley 19.628/21.719, no HIPAA, pero el mecanismo de resguardo es el mismo. Para datos de pacientes es una condición habilitante, no opcional.
No entrenamiento con tus datos En ambos planes los prompts no se usan para entrenar los modelos, por defecto. No es un diferenciador entre planes. La protección extra está en la retención (ZDR / ventana personalizada), no en el entrenamiento.
Facturación Team factura mensual o anual (la página deja ajustarlo). Enterprise solo anual, sea autoservicio o con ventas. Define flexibilidad presupuestaria: Enterprise implica compromiso de contratación anual.

Conceptos detrás de los controles

Asientos Standard vs Premium precios

El asiento es la unidad de licencia por persona. Standard ($20/mes anual, $25 mensual) cubre el uso estándar de la suite (chat, docs, Claude Code incluido). Premium ($100/mes anual, $125 mensual) da 5x más capacidad de uso que Standard, pensado para quien usa Claude Code o Cowork de forma intensiva.

En la página, el select de cada grupo decide qué tipo de asiento se licencia.

Consumo API / Claude Platform por token

Separado de los asientos: se paga por token, no por persona. Es lo que mueve agentes, MCP y RAG (DREAMS, vault, reportería).

  • Sonnet 5: $2/$10 por millón de tokens (entrada/salida) — trabajo de agentes.
  • Haiku 4.5: $1/$5 — indexado masivo y clasificación barata.
  • Opus 5.5: $4/$20 — razonamiento pesado.

DPA y BAA contractual

El DPA (Data Processing Agreement) es el acuerdo estándar de tratamiento de datos. El BAA (Business Associate Agreement) es específico de la ley HIPAA de EE.UU. para información de salud (PHI).

  • Ninguno se activa solo: se firma contactando al equipo comercial de Anthropic.
  • Para Chile aplica la Ley 19.628/21.719; el mecanismo técnico de resguardo es el mismo.

ZDR — Zero Data Retention solicitar

Con ZDR, Anthropic no guarda tus prompts ni respuestas después de responder, salvo lo mínimo exigido por ley o para prevenir abuso.

  • Requiere aprobación de Anthropic (cuenta calificada); no es un switch autoservicio.
  • Aplica a API/Enterprise. En Enterprise también se puede fijar una ventana de retención personalizada en vez del cero total.

Mezcla de asientos recomendado

No todos necesitan Premium. Se recomienda dejar Premium solo para quienes viven en Claude Code (el equipo TI del refactor) y Standard para gerencias y usuarios generales.

En Enterprise todos quedan en el mismo asiento base ($20/mes) y la diferencia se mueve al consumo API.

Cómo decide esta calculadora lógica

La recomendación es determinista y respeta este orden de prioridad:

  • Datos sensibles marcados → Enterprise: con datos de pacientes los controles (RBAC, audit, BAA/DPA, retención) no son opcionales, aunque cueste lo mismo.
  • Sin sensibles y ≤15 asientos → Team: más simple de administrar y costo empaquetado predecible.
  • Sin sensibles y >15 asientos → Enterprise: SSO avanzado, SCIM y analítica de uso para administrar muchas cuentas.

El costo no es el único factor: el checkbox de datos sensibles manda primero.

Gasto API estimado insumo

Es el campo USD/mes separado de los asientos. En Enterprise ese consumo se suma tal cual al costo (asientos + API); en Team la misma capacidad de agentes se paga vía asientos Premium.

Para tomar decisiones sin errores, este número debería medirse en el piloto (con datos sintéticos) antes de presupuestar en serio.

Precios de referencia (USD, sin impuestos) según claude.com/pricing — pueden cambiar. Para datos de pacientes, cierra BAA/DPA y ZDR con el equipo comercial de Anthropic antes de operar con información real.
